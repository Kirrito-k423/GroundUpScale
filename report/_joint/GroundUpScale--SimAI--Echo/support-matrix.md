# GroundUpScale vs SimAI vs Echo 全量能力支持度联评

## 分析元数据

- 联评日期：2026-08-10；结论时效截至该日。
- GroundUpScale：<https://github.com/Kirrito-k423/GroundUpScale>，固定提交 `4a6ac7aee0500d10c32ee7463daf24c8a20a5dd2`。
- SimAI：<https://github.com/aliyun/SimAI>，固定提交 `f5efb5a93ea9be7db25a8843f9f7ff54044f6062`；同时固定 AICB `23eec3c48ca2d2d93dd888a4c7b22ab4421e782f`、SimCCL `403610a0f91659e628428afa8d489cb046ef9503`、ns-3 `7e3cb5b88c99abcb582c5abc3919484a4805111b`。
- Echo：<https://github.com/NetX-lab/Echo>，固定提交 `15f0d12c417459d7a1b3b66abeaa28eca0b841a2`；同时固定 slowdown `7d698a77c0318f2b706ed27d3f6221f8b1e0a349`、workload-tracer `8fb57b6cdc8d5b5505ea4705e6cdf0684bb77424`。
- 支持状态只表示固定提交的公开、可定位能力。论文声称但主仓未公开的实现，一律不标为“支持”。“模型支持”若只是生成 mocked workload，也明确标注，不等同于加载权重或正确训练。
- 决策口径：GroundUpScale 不应复刻 SimAI 的网络仿真和 collective 引擎，也不应等待 Echo 未公开组件；应转为可接入两者证据的“可信性能证据编译器 / 诊断层”。

## 证据与限制

- 本报告是源码、文档、测试、论文和 GitHub 元数据的静态联评；除 GroundUpScale 测试外，没有在本机重建 SimAI 的 CUDA/ns-3 全栈或 Echo 的 NVIDIA Nsight 数据链。
- GroundUpScale 固定基线独立测试为 349 passed。当前用户工作树测试为 388 passed、1 failed；失败来自硬件 microbenchmark eligible shape 数 9/10，隔离重跑通过，因此应视为环境/顺序敏感问题而非稳定通过。
- SimAI NSDI'25 的 98.1% 平均训练对齐与通信误差数字只适用于论文给定 A100/H100、128–1024 GPU、GPT/LLaMA 场景，不能外推到后来加入的推理代码。[论文页](https://www.usenix.org/conference/nsdi25/presentation/wang-xizheng-simai)
- Echo 的约 91.4% 论文准确率、96×H800 GPT-175B 约 8% 误差和 128 GPU 约 83 秒，属于论文系统；固定主仓没有公开完整 E2E 引擎。[论文](https://arxiv.org/abs/2412.12487)
- GitHub stars、forks、提交数只作为维护成熟度旁证，不作为技术价值或正确性的直接证据。
- 三仓都不是 SFT/LoRA/GRPO/PPO/OPD 等训练算法框架；“支持模型”主要指性能 workload、trace 或配置覆盖。
